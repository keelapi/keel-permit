# Human Permit Artifact and Package v1

This contract defines the default human presentation of a verified Permit and
the inventory format for a legacy downloadable `.keelpermit` package. The
default customer download is a compact, signed, human-readable JSON evidence
bundle named for its consequence-specific AI Permit-to-X title. It does not
create authority, change a Policy decision, or introduce a new trust root.

## 1. Trust model

The signed Permit and evidence pack remain authoritative. A human artifact is a
deterministic projection produced from fields the verifier has actually
verified. The renderer MUST ignore caller-supplied titles and summaries.

The package manifest is non-authoritative inventory. A verifier MUST:

1. locate the signed evidence declared by the package;
2. verify that evidence under the selected trust mode;
3. resolve the pinned semantic and presentation artifacts;
4. regenerate the human title and summary from verified fields; and
5. compare packaged human material with the regenerated result before
   presenting it as verified.

Changing `permit.html`, `summary.txt`, or the package manifest cannot change the
authorization or verifier verdict. Changing signed evidence must fail its
cryptographic verification.

## 2. Default presentation

The default view is human-readable. Raw JSON, canonical signed bytes, hex,
Base64, signatures, digests, and contract pins are advanced representations.

A successful issued authorization renders the profile title derived from the
verified semantic, for example `AI Permit-to-Refund-Payment`. A denied request renders
`AI Action Denied`. A request awaiting review renders
`AI Action Awaiting Approval`. Denials and review requests are never described
as Permits.

Provider outcome is a state label, not part of the authority title. A valid
Permit can coexist with provider rejection or an unknown external outcome.

## 3. Lifecycle fields

Every issued Permit view includes:

- `issued_at` as recorded by the issuer;
- effective `expires_at`, including `null` only where the signed Permit permits
  an unbounded lifetime;
- current status; and
- available use, dispatch, expiry-source, revocation, and verification times.

`issued_at` is not a Policy-authored timestamp. Policy, requested lifetime,
parent authority, and platform limits may constrain the effective
`expires_at`. Renderers MUST keep issuance, dispatch, provider observation,
artifact generation, and verification times distinct.

## 4. Summary

Every human artifact ends with a plain-language summary. The summary is
generated by the verifier from verified structured fields using the
`verifier_from_verified_fields` derivation. Missing values are omitted and are
never inferred or invented.

[`semantics/permit/human_summary_v1.json`](../semantics/permit/human_summary_v1.json)
defines the exact template set, sentence order, normalization, and security
posture. Strings are normalized to Unicode NFC, leading and trailing whitespace
is removed, and internal whitespace runs collapse to one ASCII space. The
verified RFC 3339 timestamp representation is preserved. Output is one UTF-8
paragraph with single spaces between sentences and no terminal newline.

The summary is presentation, not a verifier claim. If packaged summary text
does not match the verifier-regenerated text, the packaged human view is not
trusted even when the underlying signed evidence remains valid.

## 5. Evidence boundary

The human artifact states both what the selected evidence establishes and what
it does not establish. Provider API responses and later provider readback are
labelled Keel-mediated observations unless independently signed provider
attestation is verified.

## 6. Package layout

`schemas/permit-package-manifest-v1.schema.json` defines a safe relative-path
inventory. A package contains at least:

```text
manifest.json
permit.html
verification-report.json
evidence/permit-exact.json
```

Optional advanced files include canonical bytes, hex or Base64 encodings,
signatures, digests, and embedded contract artifacts. Archive paths are
relative and path traversal is forbidden.

The package extension is a transport convention. Offline verification is
anchored in the signed evidence and explicitly selected trust key, not in the
extension, archive container, HTML, or manifest.
